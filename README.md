# 📖 Полный мануал: автоматическая система блогов с реф-ссылками Creative Fabrica

Эта система каждый день сама:
1. Придумывает тему и пишет статью (через DeepSeek)
2. Генерирует обложку и вторую иллюстрацию через DeepInfra (модель FLUX-1-schnell)
3. Загружает обе картинки на imgbb.com и получает прямые ссылки
4. Сохраняет статью (с картинками и твоей реф-ссылкой) в репозиторий
5. Cloudflare Pages автоматически публикует сайт

Всё бесплатно/почти бесплатно (DeepInfra тарифицируется по использованию, но стоимость генерации картинок очень низкая), всё работает по расписанию само, без сервера 24/7.

---

## 🧩 Из чего состоит система

```
content-engine/
├── config/
│   ├── sites.json             ← список твоих сайтов (ниши, домены, тон, стиль письма)
│   └── cf_links.json          ← ссылки на категории Creative Fabrica по нишам
├── scripts/
│   ├── deepseek.js            ← пишет и переписывает статьи
│   ├── imagegen.js            ← генерирует картинки (DeepInfra / FLUX-1-schnell)
│   ├── imgbb.js                ← загружает картинки на imgbb.com
│   ├── links.js                ← выбирает релевантную реф-ссылку по нише
│   ├── keywords.js            ← бесплатные подсказки Google Autocomplete
│   ├── generate.js            ← главный скрипт ежедневной генерации
│   └── refresh-posts.js       ← обновление старых статей
├── sites/                      ← сюда складываются готовые статьи (по папкам на сайт)
├── .github/workflows/
│   ├── daily-post.yml         ← ежедневная генерация
│   └── weekly-refresh.yml     ← еженедельное обновление старых статей
└── package.json
```

## ШАГ 1. Создай репозиторий на GitHub

1. Зайди на github.com → New repository
2. Назови например `content-engine`
3. Сделай Public или Private (без разницы для функционала)
4. Залей туда все файлы из этой системы (просто скопируй структуру выше)

---

## ШАГ 2. Получи DeepSeek API ключ

1. Зайди на platform.deepseek.com
2. Зарегистрируйся
3. В разделе **API Keys** создай новый ключ
4. Скопируй его — он понадобится на шаге 5

---

## ШАГ 3. Получи API-ключ DeepInfra (для генерации картинок)

1. Зайди на deepinfra.com → зарегистрируйся
2. В разделе **API Keys** в личном кабинете создай новый ключ
3. Скопируй его — понадобится на шаге 5

Используемая модель — `black-forest-labs/FLUX-1-schnell`, она быстрая и недорогая, отлично подходит для обложек статей.

---

## ШАГ 4. Получи ключ imgbb

1. Зайди на api.imgbb.com
2. Зарегистрируйся / войди
3. Получи **API key** (бесплатно, без лимита по сути для твоих объёмов)

---

## ШАГ 5. Добавь все ключи в GitHub Secrets

Это безопасное хранилище — ключи не видны в коде.

1. Открой свой репозиторий на GitHub
2. **Settings** → **Secrets and variables** → **Actions**
3. Жми **New repository secret** и добавь по очереди:

| Имя секрета | Значение |
|---|---|
| `DEEPSEEK_API_KEY` | ключ из шага 2 |
| `DEEPINFRA_API_KEY` | ключ из шага 3 |
| `IMGBB_API_KEY` | ключ из шага 4 |

## 🆕 Обновления v3: DeepInfra (FLUX), две картинки, длиннее статьи, авто-обновление старого контента

### Смена сервиса картинок: Cloudflare Worker → DeepInfra (FLUX-1-schnell)

Больше не нужен Cloudflare Worker для картинок. Используется DeepInfra API с моделью `black-forest-labs/FLUX-1-schnell` — качество выше, настройка проще (см. ШАГ 3 выше).

### Две картинки на статью вместо одной

DeepSeek теперь генерирует два разных промпта: `image_prompt_cover` (обложка) и `image_prompt_body` (вторая картинка, специально другой ракурс/деталь темы). Это снимает проблему одинаковых/дублирующихся картинок на одной странице. Обложка идёт в начале статьи через шаблон, вторая картинка автоматически вставляется скриптом в середину текста.

### Статьи длиннее и информативнее

Объём увеличен до 1600-2400 слов, минимум 6-8 секций (##), 3-4 из них с подсекциями (###), FAQ увеличен до 4-5 вопросов.

### Разные стили письма на каждом сайте

Новое поле `writing_style` в `config/sites.json` (отдельно от `tone`) — один сайт пишет короткими фразами, другой длинными плавными предложениями. Контент на разных сайтах не выглядит шаблонным.

### Бесплатная проверка реальных запросов людей

`scripts/keywords.js` перед каждой генерацией бесплатно запрашивает Google Autocomplete по теме ниши и передаёт реальные подсказки в DeepSeek. Не требует ключей. Если Google изменит формат ответа — скрипт просто продолжит работу без подсказок (не критично).

### Защита от повторения тем

Скрипт читает заголовки уже опубликованных статей сайта и просит DeepSeek не повторять темы.

### Автоматическое обновление старых статей

Новый `scripts/refresh-posts.js` + `.github/workflows/weekly-refresh.yml`: каждый понедельник берёт самую старую статью каждого сайта, просит DeepSeek переписать её подробнее и актуальнее, сохраняя заголовок и URL (чтобы не терять SEO-вес страницы). Количество статей за раз регулируется переменной `REFRESH_POSTS_PER_SITE` в workflow-файле.

## ШАГ 6. Настрой список сайтов

Открой файл `config/sites.json` — там уже есть 3 примера сайтов. Просто меняй/добавляй блоки:

```json
{
  "id": "site4",
  "domain": "твой-домен.pages.dev",
  "niche": "описание ниши на английском (для лучших промптов)",
  "lang": "en",
  "active": true,
  "posts_per_run": 1
}
```

- `id` — уникальное имя, под ним будет создана папка `sites/id/posts/`
- `active: false` — если хочешь временно "выключить" сайт без удаления из конфига
- `posts_per_run` — сколько статей писать за один запуск (обычно 1)

## ШАГ 7. Проверь, что всё работает (запуск вручную)

1. Зайди в свой репозиторий на GitHub → вкладка **Actions**
2. Слева выбери workflow **"Ежедневная генерация статей"**
3. Справа нажми **Run workflow** → **Run workflow** (зелёная кнопка)
4. Подожди 1-2 минуты, обновляй страницу
5. Если всё ок — увидишь зелёную галочку, и в папке `sites/.../posts/` появятся новые `.md` файлы со статьями

Если что-то красное (ошибка) — открой лог запуска, там будет написано на каком шаге проблема (неправильный ключ, не включён AI binding и т.д.)

## ➕ Как добавить 11-й, 12-й сайт позже

1. Добавь новый блок в `config/sites.json` (см. Шаг 6)
2. Запусти `node scripts/init-site.js <id>` локально (или просто запусти весь workflow — папка создастся автоматически сама при следующей генерации, скрипт `generate.js` сам копирует шаблон, если папки сайта ещё нет)
3. Подключи новую папку как отдельный проект в Cloudflare Pages (см. Шаг 8)

То есть добавление нового сайта = 1 строка в конфиге + 1 раз настроить Pages-проект. Дальше всё работает само.

## ШАГ 8. Подключи Cloudflare Pages к сайтам (чтобы статьи стали реальными страницами)

Каждая папка `sites/site1`, `sites/site2`... — это уже полноценный 11ty-сайт (дизайн + структура добавлены автоматически). Осталось подключить каждую папку как отдельный проект в Cloudflare Pages.

### Что уже готово в каждой папке `sites/<id>/`
- `.eleventy.js` — конфигурация сборки
- `_includes/base.njk` — общий дизайн (шапка, стили, футер)
- `_includes/post.njk` — шаблон страницы статьи (с обложкой и CTA-блоком на Creative Fabrica)
- `index.njk` — главная страница со списком статей (карточки с картинками)
- `_data/site.js` — название сайта (можно поменять переменными окружения `SITE_NAME` в Cloudflare)
- `posts/` — сюда генератор кладёт `.md` файлы статей

### Подключение в Cloudflare Pages (для каждого сайта свой проект)

1. dash.cloudflare.com → **Workers & Pages** → **Create application** → вкладка **Pages** → **Connect to Git**
2. Выбери свой репозиторий `content-engine`
3. **Project name**: например `site1-fonts` (это и станет частью URL `site1-fonts.pages.dev`, если не подключать свой домен)
4. **Build settings**:
   - **Root directory (advanced)**: укажи `sites/site1` (именно эта настройка позволяет держать все сайты в одном репозитории — Cloudflare будет собирать только эту подпапку)
   - **Build command**: `npm install && npm run build`
   - **Build output directory**: `_site`
5. (Опционально) **Environment variables**: можно добавить `SITE_NAME` = "Cricut Fonts Hub" для красивого названия сайта
6. **Save and Deploy**

Через 1-2 минуты сайт будет доступен на `https://site1-fonts.pages.dev`.

7. Повтори то же самое для `sites/site2`, `sites/site3` и т.д. — каждый раз создаёшь новый Pages-проект с другим Root directory.

### Подключение своего домена (если купишь за ~2€)

В настройках Pages-проекта → **Custom domains** → **Set up a custom domain** → следуй инструкции (нужно будет добавить DNS-запись у регистратора домена, либо перенести DNS на Cloudflare — тогда всё настраивается в 1 клик).

### Автообновление при новых статьях

Это уже работает "из коробки": GitHub Actions каждый день коммитит новые `.md` файлы в `sites/<id>/posts/` → Cloudflare Pages видит новый коммит в подключённой папке → автоматически пересобирает и публикует сайт. Никаких дополнительных действий не нужно.

## 📄 Новые страницы сайта (About, Contact, Privacy Policy, Affiliate Disclosure)

Каждый сайт теперь автоматически включает 4 дополнительные страницы — это важно по двум причинам:
- **Индексация и доверие у Google.** Сайты без About/Privacy/Contact выглядят менее надёжными для поисковика (это часть E-E-A-T сигналов — Experience, Expertise, Authoritativeness, Trust)
- **Требование рекламных сетей.** Google AdSense и большинство других сетей **не одобрят сайт без Privacy Policy** — это одно из первых, что они проверяют

Страницы уже добавлены в навигацию (шапка и футер) и в `sitemap.xml` автоматически — ничего вручную линковать не нужно.

### Что стоит донастроить руками

- В `contact.njk` сейчас placeholder-email — задай переменную `SITE_CONTACT_EMAIL` в Cloudflare Pages (Settings → Environment variables), как и `SITE_NAME`, `SITE_BASE_URL`
- Текст Privacy Policy и Affiliate Disclosure — общий, безопасный шаблон, но если планируешь подавать на AdSense — рекомендую один раз вычитать текст самостоятельно и убедиться, что он соответствует именно твоей ситуации (например, если добавишь Google Analytics — упомяни это явно в Privacy Policy)

Система теперь генерирует более качественный, структурированный контент:

- **Тон и аудитория на сайт** — поля `tone` и `target_audience` в `config/sites.json` делают статьи на разных сайтах разными по стилю (не шаблонными)
- **Разные типы статей** — каждый раз случайно выбирается формат (топ-N, инструкция, сравнение с таблицей, разбор ошибок, подборка идей) — разнообразие контента
- **FAQ-блок** — каждая статья получает 3-4 вопроса-ответа в конце + валидную Schema.org FAQPage разметку (JSON-LD) — помогает попадать в Google Featured Snippets
- **Meta description** — теперь генерируется отдельно, строго 120-155 символов, с ключевым словом в начале
- **Описательный alt-текст** картинки — не дублирует заголовок целиком
- **Markdown-таблицы** для сравнений — рендерятся как настоящие HTML-таблицы
- **sitemap.xml и robots.txt** — генерируются автоматически на каждом сайте, помогают Google быстрее находить и индексировать новые статьи
- **Open Graph и Twitter Card теги** — статьи красиво отображаются при шеринге в соцсетях
- **Canonical URL** — защита от проблем с дублирующимся контентом

### Важно: укажи `SITE_BASE_URL` в Cloudflare Pages

Для корректной работы sitemap.xml, canonical-ссылок и Open Graph тегов нужно добавить переменную окружения в настройках каждого Pages-проекта:

- **Settings** → **Environment variables** → добавь `SITE_BASE_URL` = реальный адрес сайта (например `https://fonts-for-cricut.pages.dev` или твой кастомный домен, БЕЗ слэша на конце)

Без этой переменной ссылки в sitemap/OG-тегах будут пустыми — сайт всё равно будет работать, но эти SEO-плюшки не сработают.

---



По умолчанию система запускается **каждый день в 9:00 UTC**. Поменять можно в файле `.github/workflows/daily-post.yml`, строка:

```yaml
- cron: "0 9 * * *"
```

Формат: `минута час * * *` (время всегда по UTC). Например, для запуска в 12:00 по Риге (летом UTC+3) нужно ставить `0 9 * * *` — как сейчас и стоит.

## 🔒 Важно про безопасность

- Никогда не пиши API-ключи прямо в код или в config файлы — только через GitHub Secrets
- Реф-ссылка Creative Fabrica зашита в `scripts/generate.js` — если её нужно поменять, она там в одном месте: `REF_LINK`

## ❓ Частые проблемы

| Проблема | Решение |
|---|---|
| "Не задан DEEPSEEK_API_KEY" | Проверь, что секрет добавлен в GitHub Secrets именно с таким именем |
| Картинка не генерируется, но статья сохраняется | Это нормально — скрипт продолжит работу без картинки, проверь AI binding в Cloudflare Worker |
| imgbb выдаёт ошибку | Проверь правильность ключа, иногда нужно подождать после регистрации (до 10 минут) |
| Workflow не запускается по расписанию | GitHub иногда отключает cron у неактивных репозиториев — просто зайди и запусти руками раз, или сделай любой commit |
