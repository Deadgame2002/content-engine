# 📖 Полный мануал: автоматическая система блогов с реф-ссылками Creative Fabrica

Эта система каждый день сама:
1. Придумывает тему и пишет статью (через DeepSeek)
2. Генерирует обложку к статье (через твой Cloudflare Worker)
3. Загружает обложку на imgbb.com и получает прямую ссылку
4. Сохраняет статью (с картинкой и твоей реф-ссылкой) в репозиторий
5. Cloudflare Pages автоматически публикует сайт

Всё бесплатно, всё работает по расписанию само, без сервера 24/7.

---

## 🧩 Из чего состоит система

```
content-engine/
├── config/sites.json          ← список твоих сайтов (ниши, домены)
├── scripts/
│   ├── deepseek.js            ← пишет статью
│   ├── imagegen.js            ← генерирует картинку (Cloudflare Worker)
│   ├── imgbb.js                ← загружает картинку на imgbb.com
│   └── generate.js            ← главный скрипт, который всё соединяет
├── sites/                      ← сюда складываются готовые статьи (по папкам на сайт)
├── .github/workflows/
│   └── daily-post.yml         ← расписание автозапуска (GitHub Actions)
└── package.json
```

## ШАГ 1. Создай репозиторий на GitHub

1. Зайди на github.com → New repository
2. Назови например `content-engine`
3. Сделай Public или Private (без разницы для функционала)
4. Залей туда все файлы из этой системы (просто скопируй структуру выше)

---

## ШАГ 2. Получи DeepSeek API ключ

1. Зайди на platform.deepseek.com
2. Зарегистрируйся
3. В разделе **API Keys** создай новый ключ
4. Скопируй его — он понадобится на шаге 5

---

## ШАГ 3. Настрой Cloudflare Worker для картинок

(Если уже сделал по прошлому мануалу — пропусти, просто возьми готовый URL и API_KEY)

1. dash.cloudflare.com → Workers & Pages → Create Worker
2. Вставь код из `worker.js` (репозиторий saurav-z/free-image-generation-api)
3. Settings → Variables → добавь `API_KEY` = свой секретный пароль
4. Workers & Pages → AI → Enable
5. В настройках воркера → Service bindings → добавь binding `AI` → Workers AI
6. Скопируй URL воркера (вида `https://имя.поддомен.workers.dev`)

---

## ШАГ 4. Получи ключ imgbb

1. Зайди на api.imgbb.com
2. Зарегистрируйся / войди
3. Получи **API key** (бесплатно, без лимита по сути для твоих объёмов)

---

## ШАГ 5. Добавь все ключи в GitHub Secrets

Это безопасное хранилище — ключи не видны в коде.

1. Открой свой репозиторий на GitHub
2. **Settings** → **Secrets and variables** → **Actions**
3. Жми **New repository secret** и добавь по очереди:

| Имя секрета | Значение |
|---|---|
| `DEEPSEEK_API_KEY` | ключ из шага 2 |
| `IMAGE_WORKER_URL` | URL воркера из шага 3 |
| `IMAGE_WORKER_API_KEY` | твой `API_KEY` из настроек воркера (шаг 3) |
| `IMGBB_API_KEY` | ключ из шага 4 |

---

## ШАГ 6. Настрой список сайтов

Открой файл `config/sites.json` — там уже есть 3 примера сайтов. Просто меняй/добавляй блоки:

```json
{
  "id": "site4",
  "domain": "твой-домен.pages.dev",
  "niche": "описание ниши на английском (для лучших промптов)",
  "lang": "en",
  "active": true,
  "posts_per_run": 1
}
```

- `id` — уникальное имя, под ним будет создана папка `sites/id/posts/`
- `active: false` — если хочешь временно "выключить" сайт без удаления из конфига
- `posts_per_run` — сколько статей писать за один запуск (обычно 1)

---

## ШАГ 7. Проверь, что всё работает (запуск вручную)

1. Зайди в свой репозиторий на GitHub → вкладка **Actions**
2. Слева выбери workflow **"Ежедневная генерация статей"**
3. Справа нажми **Run workflow** → **Run workflow** (зелёная кнопка)
4. Подожди 1-2 минуты, обновляй страницу
5. Если всё ок — увидишь зелёную галочку, и в папке `sites/.../posts/` появятся новые `.md` файлы со статьями

Если что-то красное (ошибка) — открой лог запуска, там будет написано на каком шаге проблема (неправильный ключ, не включён AI binding и т.д.)

---

## ➕ Как добавить 11-й, 12-й сайт позже

1. Добавь новый блок в `config/sites.json` (см. Шаг 6)
2. Запусти `node scripts/init-site.js <id>` локально (или просто запусти весь workflow — папка создастся автоматически сама при следующей генерации, скрипт `generate.js` сам копирует шаблон, если папки сайта ещё нет)
3. Подключи новую папку как отдельный проект в Cloudflare Pages (см. Шаг 8)

То есть добавление нового сайта = 1 строка в конфиге + 1 раз настроить Pages-проект. Дальше всё работает само.

## ШАГ 8. Подключи Cloudflare Pages к сайтам (чтобы статьи стали реальными страницами)

Каждая папка `sites/site1`, `sites/site2`... — это уже полноценный 11ty-сайт (дизайн + структура добавлены автоматически). Осталось подключить каждую папку как отдельный проект в Cloudflare Pages.

### Что уже готово в каждой папке `sites/<id>/`
- `.eleventy.js` — конфигурация сборки
- `_includes/base.njk` — общий дизайн (шапка, стили, футер)
- `_includes/post.njk` — шаблон страницы статьи (с обложкой и CTA-блоком на Creative Fabrica)
- `index.njk` — главная страница со списком статей (карточки с картинками)
- `_data/site.js` — название сайта (можно поменять переменными окружения `SITE_NAME` в Cloudflare)
- `posts/` — сюда генератор кладёт `.md` файлы статей

### Подключение в Cloudflare Pages (для каждого сайта свой проект)

1. dash.cloudflare.com → **Workers & Pages** → **Create application** → вкладка **Pages** → **Connect to Git**
2. Выбери свой репозиторий `content-engine`
3. **Project name**: например `site1-fonts` (это и станет частью URL `site1-fonts.pages.dev`, если не подключать свой домен)
4. **Build settings**:
   - **Root directory (advanced)**: укажи `sites/site1` (именно эта настройка позволяет держать все сайты в одном репозитории — Cloudflare будет собирать только эту подпапку)
   - **Build command**: `npm install && npm run build`
   - **Build output directory**: `_site`
5. (Опционально) **Environment variables**: можно добавить `SITE_NAME` = "Cricut Fonts Hub" для красивого названия сайта
6. **Save and Deploy**

Через 1-2 минуты сайт будет доступен на `https://site1-fonts.pages.dev`.

7. Повтори то же самое для `sites/site2`, `sites/site3` и т.д. — каждый раз создаёшь новый Pages-проект с другим Root directory.

### Подключение своего домена (если купишь за ~2€)

В настройках Pages-проекта → **Custom domains** → **Set up a custom domain** → следуй инструкции (нужно будет добавить DNS-запись у регистратора домена, либо перенести DNS на Cloudflare — тогда всё настраивается в 1 клик).

### Автообновление при новых статьях

Это уже работает "из коробки": GitHub Actions каждый день коммитит новые `.md` файлы в `sites/<id>/posts/` → Cloudflare Pages видит новый коммит в подключённой папке → автоматически пересобирает и публикует сайт. Никаких дополнительных действий не нужно.

## ⏰ Расписание

По умолчанию система запускается **каждый день в 9:00 UTC**. Поменять можно в файле `.github/workflows/daily-post.yml`, строка:

```yaml
- cron: "0 9 * * *"
```

Формат: `минута час * * *` (время всегда по UTC). Например, для запуска в 12:00 по Риге (летом UTC+3) нужно ставить `0 9 * * *` — как сейчас и стоит.

---

## 🔒 Важно про безопасность

- Никогда не пиши API-ключи прямо в код или в config файлы — только через GitHub Secrets
- Реф-ссылка Creative Fabrica зашита в `scripts/generate.js` — если её нужно поменять, она там в одном месте: `REF_LINK`

## ❓ Частые проблемы

| Проблема | Решение |
|---|---|
| "Не задан DEEPSEEK_API_KEY" | Проверь, что секрет добавлен в GitHub Secrets именно с таким именем |
| Картинка не генерируется, но статья сохраняется | Это нормально — скрипт продолжит работу без картинки, проверь AI binding в Cloudflare Worker |
| imgbb выдаёт ошибку | Проверь правильность ключа, иногда нужно подождать после регистрации (до 10 минут) |
| Workflow не запускается по расписанию | GitHub иногда отключает cron у неактивных репозиториев — просто зайди и запусти руками раз, или сделай любой commit |
